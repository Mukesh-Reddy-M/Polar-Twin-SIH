# Contributing

## Before opening a change

- Check the MVP and current decisions in `docs/ROADMAP.md` and `docs/ARCHITECTURE.md`.
- Keep synthetic, public-derived, manual, and sensor data clearly distinguished.
- Do not commit credentials, private station data, or unverified operational thresholds.
- Keep changes small enough to review and include a short demo note for user-facing changes.

## Pull requests

Include:

- What changed and why.
- How to run or inspect it.
- Any schema/API changes and updated sample payloads.
- Screenshots or a short recording for interface changes.
- Known limitations and whether the demo remains repeatable offline.
